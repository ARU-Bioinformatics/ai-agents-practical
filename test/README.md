# Tests of the practical

These tests were used to build the practical. They are not needed to run or host it.

**Needs:** Python 3 with [Playwright](https://playwright.dev/python/) (`pip install playwright`, then `playwright install chromium`). Three tests compare the page with the real programs of the computer they run on: `t_lang.py` and `t_files.py` with bash 5.2 and the GNU tools on the `PATH` (coreutils 9, findutils, diffutils 3.10, grep, sed, awk, gzip, bc, and `getopt` and `locale` as every Linux system has them; each runs its scripts in a temporary folder of their own, which is their home folder too (`HOME`) and which it removes afterwards, with `LC_ALL=C.UTF-8` – the setting of the page's terminal –, on a file system with blocks of 4 K; the scripts change nothing outside that folder); `t_partial.py` also with native minimap2 2.22, samtools 1.17, bcftools 1.10, bgzip and jq 1.7 – it looks for them on the `PATH`, or in the folders given as `NATIVE_TOOLS=dir1:dir2` (the first folder that has a program wins), and stops with a message if one is missing. Use exactly these versions: other versions give other numbers.

```bash
bash run_all.sh            # all tests but the two that only take screenshots, about 15 minutes; summary in out/all.log
bash run_all.sh lang agent # only these
python3 t_agent.py         # one test, output on the screen
```

Each test serves the site with `../serve.py` on a port of its own and drives it in headless Chromium.

**Run them on a computer that is doing little else.** Several tests stop programs after a time, and `t_lang.py` and `t_files.py` compare with what the bash of the computer prints – which, for a few commands, depends on timing: the order in which the two parts of a pipeline print their trace under `set -x`, whether `cat F | tr x y > F` reads `F` before the shell has emptied it, the status of a command whose reader stops early while little is left to write (141 or 0). Such commands are not in these tests: the scripts of `t_lang.py` and the sequences of `t_files.py` were run by real bash eight and six times, most of them on a computer kept busy, and the two scripts whose result changed from run to run were rewritten. Real bash gives the same for all of them whether root or an ordinary user runs it.

`t_agent.py`, `t_rerun.py`, `t_walk.py`, `t_ui.py` and `t_shots.py` put a **stand-in for the AI service** in front of the page: requests to the Gemini API are answered with prepared replies. That makes the tests repeatable and free, and it means they test the page – not what a real model does. (The errors that the stand-in of `t_agent.py` gives – “busy”, the two kinds of limit, “not found” – are copies of what the real service sent on 6 October 2026.) Try the practical with a real key before a session.

`t_tools.py`, `t_threads.py`, `t_guard.py` and `t_facts.py` print what the programs did; read the logs (`out/NAME.log`).
